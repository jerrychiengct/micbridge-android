# Audio engine

Audio is processed locally. The app first prefers the Android native output rate when both endpoints advertise support (an empty list permits negotiation), then other shared rates, then advertised input rates and common Android conversion fallbacks (48, 44.1, 32, 24, 16, 96, 22.05 and 8 kHz). Supported rates are limited to 8–192 kHz. Mono and stereo capture configurations are attempted:

`Selected microphone → rumble filter / tone / 3-band EQ → voice care → pitch → grit → speech compressor → robot modulation → echo → gain / limiter → selected output`

Natural mode bypasses creative stages with neutral settings. Effects can also be bypassed with the switch. Pitch uses two interpolated, crossfaded delay taps with a 40 ms window. It is an approximate creative effect and can produce grain or warble; it is not a professional formant-preserving pitch processor. Robot texture uses 70 Hz ring modulation. Echo uses a feedback delay with selectable spacing and blend. Tone is a crossover-based warm/bright tilt. Separate EQ bands use a 180 Hz low shelf, a 1.5 kHz peaking mid filter (Q 0.8), and a 4 kHz high shelf. Live EQ changes ease across blocks. Grit blends a soft tanh saturation stage with the original signal. Speech leveling uses a −18 dBFS envelope threshold, roughly 2.5:1 compression, 10 ms attack and 180 ms release, without automatic makeup gain. Vigilante combines −5 semitones, a warmer tone, bass boost and 35% grit; it is an approximation, not an exact actor or character imitation. The final causal limiter bounds digital output to roughly 90% full scale with immediate peak attenuation and an 80 ms exponential release. Its result is independent of processing-block boundaries; it adds no look-ahead. Mute clears delayed effect tails and filter / voice-care state inside the app.

Voice care uses a calibrated or conservative default noise floor for a soft downward expander. This reduces quiet background between phrases, not noise mixed into speech. The gate opens over 1 ms and closes over 20 ms with sample-rate-aware coefficients. Calibration estimates variance to avoid treating a constant microphone DC offset as background noise. Level assist avoids floor-only input and bounds gain to 0.5–2.0×. De-essing reduces the upper band when its envelope dominates; it is best-effort software processing, not AI restoration. It adds no intentional look-ahead buffer. These controls are optional, and Natural or Effects bypass preserves neutral processing. Heavy hiss, clipping, poor mic placement or a defective adapter cannot be fixed regardless of hardware quality.

Bluetooth buffering cannot be removed by this app. Pitch processing and echo alter timing further. Mute/Stop prevent new audio from being submitted, but already buffered Bluetooth audio may continue briefly. If acoustic feedback occurs, lower the speaker's physical volume or power it off. The limiter cannot prevent feedback or repair clipping at the microphone transmitter.

## Connected-device identity

Both selectors are built from a single `AudioManager.getDevices(GET_DEVICES_ALL)` snapshot. Source/sink flags and supported route categories determine each list. Repeated Android IDs are removed; product names are never used to merge distinct endpoints. Same-name ports are numbered, and media versus LE Audio profiles are labelled separately. Hands-free SCO, phone earpiece, safe-speaker aliases, unknown and virtual system endpoints are excluded. This engine does not establish a Bluetooth communication session.

Rows carry their own device ID. Selection restoration uses that ID; a missing ID returns to an explicit prompt. Before starting, the app takes a fresh snapshot and resolves both selections again. AudioRecord/AudioTrack preferences must be accepted, then their actual routed device IDs must match before voice is enabled. A changed route stops the session. Addresses and device choices are not persisted.

Android references: [AudioManager.getDevices](https://developer.android.com/reference/android/media/AudioManager#getDevices(int)), [AudioDeviceInfo](https://developer.android.com/reference/android/media/AudioDeviceInfo), [preferred versus actual routing](https://developer.android.com/reference/android/media/AudioRouting). A preferred device does not guarantee the actual route; hardware validation is still necessary.

## Latency and overload recovery in 0.5.1

Fast mode uses a native output burst when the negotiated rate matches the native rate and the reported burst is between 2 and 10 ms; otherwise it uses approximately 5 ms blocks. Balanced mode uses approximately 10 ms blocks. Android properties describe a recommended default path, not a guarantee for every selected external route. The actual route and performance mode are still checked.

The output allocation reserves at least 80 ms of capacity for recovery, but its **effective buffer** starts at two Fast blocks or about 40 ms in Balanced mode. Allocated capacity is not the amount of audio queued. Android may clamp the effective size. On Android 12+, the start threshold follows the initial effective buffer. Fast mode samples underruns once per second, ignores the initial startup interval, grows by one block after new underruns, and probes one block smaller after ten stable seconds. A failed probe raises the tuning floor to avoid repeated oscillation. Growth is capped at Android's actual capacity.

The worker drains available capture with nonblocking reads before processing. A mono FIFO preserves ordinary frame order. Its pending budget is at least 20 ms in Fast mode or 40 ms in Balanced mode, enlarged to the reported capture buffer when necessary, capped at 200 ms for that enlargement. The nonblocking drain is limited to at most 64 reads per iteration, so it cannot starve output indefinitely. Overload discards the oldest pending capture, retains recent speech and eases the first 2 ms after a discontinuity. Normal capture is bit-exact before DSP. This trades lost audio under overload for bounded app delay; it is not clock-drift resampling or Bluetooth buffer removal. Sustained trimming, missing syllables or crackles require a hardware report and comparison with Balanced mode.

Live shows processing-block duration, effective output buffer, reported capture buffer, output underruns and cumulative discarded-capture duration. None is an acoustic latency measurement. The capture FIFO budget does not include Bluetooth, driver or speaker buffering. Input and output use one audio-priority Java worker; writes can still block. Settled EQ coefficients are cached and the DSP path performs no per-block array allocation. A native callback engine would be a separate architecture change requiring Android-device validation.

Implementation references: [Android low-latency guidance](https://source.android.com/docs/core/audio/latency/app), [AudioRecord blocking/nonblocking reads](https://developer.android.com/reference/android/media/AudioRecord), [AudioTrack effective buffer, underruns and start threshold](https://developer.android.com/reference/android/media/AudioTrack).
